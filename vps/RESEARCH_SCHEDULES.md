# VPS 持續公開研究排程

VPS-RESEARCH-SCHEDULE-007；WISH-CRAWL-001 的第一階段，整體仍 PARTIAL。正式入口在 Models → 全球研究，或設定 → 研究的同一個工作區。維持單一 Go／SQLite 與現有研究 runner，沒有新增常駐服務。

## 實際操作

1. 在「研究來源」保存啟用的公開 HTTPS JSON／HTML 來源；或在設定保存 Brave Search／AA 的獨立整合 Key。
2. 按「新增排程」，設定名稱、15–10080 分鐘間隔、每輪 1–200 次 HTTP、每日 1–2000 次 HTTP、公開來源及探索語言。可選網路探索、AA 榜單與已保存的 LMSpeed 線索。
3. 保存後保持停用，再按「啟用排程」。目前服務會立即檢查，離開網頁仍由該服務執行；程序必須持續運作。App 內嵌引擎停止後不宣稱有 OS 背景能力。只補最新到期輪次，不把離線期間每個錯過時段補跑一遍。
4. 卡片顯示上輪／下次檢查、執行／等待／暫停／額度原因、每輪及今日用量、研究摘要。排程紀錄顯示最近 100 輪並可打開原始工作／結果；全部歷史繼續保留。
5. 「暫停本輪」保留進度，程序重啟仍暫停；「接續本輪」或「立即研究」明確接續。「停用排程」會暫停該排程所有未完成工作並取消正在進行的 HTTP，重啟不會自行再啟用。舊的通用研究恢復 API 也不能繞過停用狀態。
6. 停用後才能編輯。保存新定義會結束尚未完成的舊輪次，保留任務、結果與用量；編輯不清掉當日計數。「取消研究」只結束該輪；要停止後續輪次請停用排程。

公開資料只有未驗證主張時，繼續留在完整漏斗，不能直接變成 VERIFIED 或加入 My Models。普通 eligibility 仍要求 RPD ≥100 **且** TPD ≥1,000,000；AA 最新有效 top-4 例外與 Unknown、free／trial／來源 scope 規則不變。

| 到期去重 | 建立 ResearchRun、更新 next_at 與唯一 schedule_id＋scheduled_for 關係原子提交；全服務自動排程同時最多一輪。不降低原手動／Playground flights |

| 每日耗盡 | 不發送超額請求，也不為未發送請求產生來源失敗證據；保存本輪 checkpoint，下一個 UTC 日在相同輪次繼續 |

| 重啟接續 | 只有此主機已確認的本機排程且 durable intent=1 才自動恢復；中斷工作最多三次重播，已完成的工作不重做；單一多頁工作（例如 AA）若尚未完成，重啟／接續時會從該工作重新讀取，尚未提供逐頁 checkpoint，用量不退款；手動暫停／取消與一般手動 ResearchRun 不自動恢復 |
| 讀取失敗 | 清單與表單分開；保留 last-good 和草稿。保存已提交但清單更新失敗，只重讀清單，不重送保存請求；過期 revision 拒絕覆寫 |

這階段只做公開 discovery／inspect 與可選整合資料讀取；**不接受模型連線 Selections、MinimalInference 或 ProbeBudget**。整合 Key 保持既有 vault 與固定 origin；不送給新發現的網站。HTTP 200、模型名稱、free 字樣或最小回覆都不是免費／身份／能力的充分證明。

## 同步與來源確認

schema19 以三張新增表保存定義、輪次意圖與每日保留量。這些表和全排程上限只屬於目前引擎，不隨 workspace 或 portable 設定備份匯入另一端；完整 SQLite 備份仍包含它們。研究候選、證據、歷史、來源與版本仍按原同步契約保存。

每個本機排程只執行本機保存／啟用時已確認的來源定義。來源被本機或另一台裝置更改、停用或移除後，tick 及每次 HTTP reservation 都會檢查，停止自動執行並要求重新確認。改過來源後重新啟用會建立新輪，不能重播舊來源快照。來源不合法時需先修正。

從別台裝置匯入的研究歷史只作觀測，不能變成可執行佇列。若同步改到本機排程所屬輪次／任務／選項，原排程停止，舊工作只保留作紀錄；本機確認後由新輪開始。自己送出資料的正常同步 ACK 不會誤停自己擁有的排程。

每輪建立時讀取目前已明確啟用的研究 query／source weight 版本，再凍結實際任務；tentative 提案不會自行啟用。沿用現有反思紀錄，不將它說成已完成跨輪品質評估或自動修改程式碼。


## 公開來源暫時故障恢復

VPS-RESEARCH-RETRY-009：SOURCE／INSPECT／INSPECT_LINK 的公開HTTPS GET收到429／502／503／504，會保存本次狀態並延後重試，最多兩次自動重試。等待時會繼續處理其他到期任務；使用原worker的30秒tick，不增加常駐服務或等待中的HTTP連線。實際時間可能晚於畫面上的最早重試時間。

第一、第二次等待為30／60秒加0–5秒分散；有效Retry-After的秒數或HTTP日期是下限。站方要求超過24小時就停止自動重試並顯示原因，不把它截短後提前連線。401／403／404、其他HTTP錯誤、解析／連線／timeout錯誤不在這個自動重試範圍。

每次實際連線仍先保留每輪、排程每日與全域每日額度，失敗／取消不退額度。額度不足時沿用原等待／明確追加規則；接續到下一個預算輪不重設等待期限或兩次重試上限。重啟保留期限，只有原本已批准的本機排程能自動恢復；手動研究仍須明確恢復。暫停、取消、停用與來源變動的原限制全部保留。

「執行紀錄」顯示等待期限、恢復／停止原因及每次HTTP狀態／時間，可按「更新執行紀錄」讀取最新結果；成功後不抹去先前失敗。紀錄同步到另一台裝置只作歷史，不會自動執行。原始錯誤body與Retry-After header不進紀錄；不自動重放模型推論、私人catalog、Brave搜尋或AA分頁。

VPS-RESEARCH-ORIGIN-013候選另補跨任務／跨新週期的共同origin冷卻；下節列實際控制。Brave／AA逐頁checkpoint與退避及完整研究預算仍為後續項目，不表示整體爬蟲已完成。

## 共同網站等待

公開來源GET收到429／502／503／504後，同一HTTPS網站的其他研究會等待既有下限。大小寫、預設443與主機尾點會對應同一origin；不同port及其他網站獨立。沒有有效Retry-After時，網站連續失敗採30秒起的有界指數退避及固定分散，最長本機退避32分5秒；有效Retry-After仍可更長。成功讀取後恢復正常，較早送出的晚成功不能清掉新失敗的等待。

等待中的任務顯示「等待網站恢復」與最早連線時間，不扣每輪／每日HTTP、不增加實際嘗試次數或來源失敗證據，也不阻塞其他網站。暫停、取消、來源確認和剩餘預算仍同時生效；到期不代表繞過原執行意圖。服務重啟、新輪及UTC跨日均不清等待；排程預算接續保留原任務等待與重試歷史。

原單一任務仍最多兩次自動重試。超過24小時會停止該任務自動重試，其他任務也不能在網站期限前連線；極端超大數值停止自動恢復並顯示無法排定時間，不溢位成立即連線。本機冷卻不隨metadata同步或portable備份搬移；同步任務仍只作歷史。schema20新增控制表，保留啟動前一致快照及既有更新回復流程；無新增預設啟用或常駐服務。

## AA 逐頁恢復（VPS-AA-RECOVERY-014 候選）

全球研究與設定服務的更新榜單進入同一持久研究runner。每頁最多200筆、最多10頁；驗證指標版本、固定總頁數、has_more及跨頁模型ID後才保存。只在完整且至少4個評分模型時原子安裝榜單，部分／失敗不更新Top-4，不延長last-good期限。

429／502／503／504每頁最多自動恢復2次，等待30／60秒及固定分散值，以Retry-After為下限。程序重啟、排程預算續鏈不重抓已完成頁、不重設逐頁上限；飛行中的已核准請求也保存attempt。超過24h等待、首頁觀測24h已過、換Key（含最後一頁回應前）、版本／分頁／模型衝突停止並要求新一輪；其他網路／認證／schema錯誤不隱式重試。時效從首頁開始，不因接續刷新期限。AA API沒有提供本機可驗證的跨頁snapshot isolation；一致version／頁數及唯一ID檢查不等於瞬間一致保證。

研究HTTP、排程每日HTTP、AA固定window與逐頁attempt在一次transaction保留，任一拒絕全回滾。同步僅帶公開進度／錯誤狀態與時間，schema21本機checkpoint含正規化資料與加密credential revision的hash，不帶到其他端或portable backup。整個DB一致快照仍包含本機狀態，還原不改原intent／暫停與取消約束。Direct sync API保留明確同步相容性；Mac原生更新按鈕與Android逐頁UI、Brave分頁及其他Crawler完整待辦仍需接續。
